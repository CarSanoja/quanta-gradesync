# End-to-end run in GCP mode — 2026-08-19

First full-pipeline execution against real Google Cloud services. The API ran
locally under uvicorn (no Cloud Run deployment, no Pub/Sub subscription); every
dependency it touched was real: GCS download, Vertex Gemini grading and audit,
Vertex embeddings, Firestore checkpoints/profiles/reviews/audit trail, Firestore
vector search.

Reproduction steps: `docs/runbooks/e2e-gcp-run.md`.

### Deviation: camila-rios did not quarantine

The blurred scan (blur 2.5, contrast 0.66) was still legible to
`gemini-3.5-flash`: it graded 7.0/70 % against a human ground truth of
7.5/75 % and reported 0.98 confidence on every criterion. The confidence gate
therefore let it through. Two facts follow:

1. The engine did not guess badly — the grade is within 0.5 points of the human.
2. The gate depends on model self-reported confidence, which in this run was
   flat and high (0.95–1.00 across all 8 exams, worst criterion 0.95). It does
   not discriminate between a clean page and a degraded one, so quarantine
   volume is not currently controllable through image quality. Calibrating
   confidence (or deriving it from evidence coverage / OCR agreement rather than
   self-report) is the follow-up.

## Idempotency probe

The same push body was POSTed again after completion:

```
{"job_id":"e2e-2026-08-19-matematicas-10a-parcial1","status":"duplicate"}
```

`.local_data/sis_writes.jsonl` stayed at one event, the audit subcollection
stayed at one document, and the job record `updated_at` remained
`22:30:41.943380Z`. The webhook short-circuits on an existing checkpoint before
creating the task; `JobRunner.process` has a second guard for records already in
`completed`.

## Bugs found and fixed

| # | Symptom in GCP mode | Fix |
|---|---|---|
| 1 | `FirestoreReviewStore.list_pending` called `FieldFilter.field("status").equal(...)`, which does not exist in `google-cloud-firestore` 2.28 → `AttributeError` on every pending-review listing (verify stage, `/review/pending`, console). | `FieldFilter("status", "==", ...)` (`core/review/store.py`). |
| 2 | Same invalid `FieldFilter` call in `FirestoreDeadLetterStore._list`; the import was also placed after the closure that used it. | `FieldFilter("job_id", "==", ...)`, import hoisted (`core/resilience/dead_letter_store.py`). |
| 3 | `FirestoreVectorMemory.upsert` wrote embeddings as a plain float array, which Firestore does not index for `find_nearest`, so semantic retrieval could never match. | Wrap in `google.cloud.firestore_v1.vector.Vector` (`core/memory/vector_memory.py`). |
| 4 | `find_nearest` requires an out-of-band vector index; without it the grade stage aborted the whole job with `FailedPrecondition`. | Index created with `gcloud` (command in the runbook) **and** `FirestoreVectorMemory.query` now catches `GoogleAPICallError`, logs, and degrades to an empty context instead of failing the batch. |
| 5 | With `sis_base_url` empty, GCP mode built `HttpSISConnector` with the URL `"/grades"` (every write would fail) and `/readyz` reported the service unavailable. | `build_sis_connector` falls back to the local JSONL sink when the URL is empty, logging a warning; the readiness check no longer treats the empty URL as fatal (`tools/sis_connector.py`, `api/readiness.py`). **This is a deliberate stand-in**: the run is faithful except that grades land in `.local_data/sis_writes.jsonl` instead of a real SIS. Setting `GRADESYNC_SIS_BASE_URL` restores the HTTP connector with no other change. |
| 6 | `GET /review/{id}/page-image` returned 403 in GCP mode (`resolve_document` only serves local staging), so the console review card had no page image — the human-review flow the product promises. | `api/media.load_remote_document` downloads the object from GCS, restricted to `GRADESYNC_GCS_BUCKET`; `api/review.py` streams it in GCP mode. Two tests added. |
| 7 | No LLM token accounting existed: `gen_ai.usage.tokens` was never set, so cost per batch was unmeasurable. | `core/telemetry/usage.py` (context-scoped ledger with parent chaining) fed by ADK events and by the auditor's `generate_content` response; stage spans record input/output/total tokens and call counts, grading spans record per-exam usage. This produced every number in this report. |

### Latent issue fixed by configuration and default change

`FallbackEvaluator` compares elapsed time **after** a successful primary call and,
if it exceeded `model_fallback_latency_seconds`, throws the result away and
re-grades with flash-lite (confidence × 0.9). Measured flash grading latency was
16–27 s per exam, so the shipped default of 15 s would have downgraded **every**
exam of this batch to flash-lite, doubling cost and lowering confidence toward
the quarantine threshold. The run used 180 s; the default is now 90 s
(`settings.py` plus the mirrored defaults in `runner.py`, `graph.py`,
`stages_assessment.py`), which is above the observed maximum with margin.

The semantics remain questionable: a latency budget that discards a completed,
higher-quality result is waste, and a real deadline (`asyncio.wait_for` around
the primary call) would be the honest implementation. That change alters the
behaviour asserted by `tests/resilience/test_repair_fallback.py` and was left
for a deliberate decision.

## Other observations (not fixed)

- **Event shape.** The webhook parses the engine's own job event, not a GCS
  `OBJECT_FINALIZE` notification. The bucket notification to `exam-batch-ingest`
  therefore cannot reach the service unchanged: a translation step must derive
  `job_id`, `exam_batch_prefix`, `class_id` and `subject` from the object path
  before the push. Nothing in the repo does this yet.
- **`catalog-defaults.json` is bucket-global**, read from the bucket root only.
  Multiple schools or terms sharing a bucket cannot have different bindings.
- **Collection sharing.** Rubric embedding documents and class competency
  snapshots both live in `competencies`; they do not collide (different id
  spaces) but the vector index and the snapshot documents are mixed.
- **Faithfulness verification is inert in GCP mode** because it relies on `.txt`
  sidecars next to the fetched files, which GCS batches do not carry.
- **Embedding calls are not token-metered**, so the cost figures omit them.
